# ActivityFlow — Premium Design System

**Version:** 1.0.0
**Platform:** Windows 10 / Windows 11
**Framework:** Python + PySide6
**Language:** Persian (Farsi)
**Layout:** Right-to-Left (RTL)
**Style:** Premium Dark · Modern · Minimal · Elegant

---

## 01. Design Philosophy

ActivityFlow یک نرم‌افزار حرفه‌ای برای ثبت، مدیریت و تحلیل فعالیت‌های روزانه است. رابط کاربری باید مدرن، مینیمال، زیبا و مناسب استفاده طولانی‌مدت باشد.

### Principles

* **Premium:** ظاهر حرفه‌ای با جزئیات دقیق و هماهنگ.
* **Minimal:** حذف عناصر غیرضروری و جلوگیری از شلوغی.
* **Functional:** اولویت با کاربردپذیری و دسترسی سریع.
* **Consistent:** استفاده از قواعد یکسان در تمام صفحات.
* **Persian-first:** پشتیبانی کامل از زبان فارسی و چینش RTL.
* **Comfortable:** کنتراست مناسب و خستگی بصری کم.
* **Responsive:** سازگاری با اندازه‌های مختلف پنجره.

## 03. Typography

### Font family

فونت اصلی: `Vazirmatn`

فونت‌های جایگزین:

`Segoe UI, Tahoma, sans-serif`

در صورت امکان، فونت Vazirmatn به‌صورت محلی در پروژه قرار گیرد.

### Type scale

| Token              | Size | Weight | Usage        |
| ------------------ | ---: | -----: | ------------ |
| `FONT_DISPLAY`     | 30px |    700 | عنوان اصلی   |
| `FONT_H1`          | 26px |    700 | عنوان صفحه   |
| `FONT_H2`          | 21px |    600 | عنوان بخش    |
| `FONT_H3`          | 17px |    600 | عنوان کارت   |
| `FONT_BODY`        | 14px |    400 | متن معمولی   |
| `FONT_BODY_MEDIUM` | 14px |    500 | متن برجسته   |
| `FONT_SMALL`       | 12px |    400 | توضیحات      |
| `FONT_CAPTION`     | 11px |    400 | اطلاعات کمکی |

### Typography rules

* از بیشتر از سه وزن فونت در یک صفحه استفاده نشود.
* فاصله خطوط متن فارسی مناسب باشد.
* عناوین کوتاه و مشخص باشند.
* اعداد، تاریخ‌ها و ساعت‌ها یکپارچه نمایش داده شوند.
* از متن‌های بیش‌ازحد کوچک در جدول‌ها اجتناب شود.

## 06. Elevation and Shadows

### Elevation levels

* **Level 0:** پس‌زمینه اصلی، بدون سایه
* **Level 1:** کارت‌ها با مرزبندی ظریف
* **Level 2:** منوهای بازشونده و پنل‌های شناور
* **Level 3:** دیالوگ‌ها و پنجره‌های مهم

### Rules

* از سایه‌های سنگین و تیره اجتناب شود.
* در تم تاریک، اختلاف سطح و مرزها مهم‌تر از سایه هستند.
* پنجره‌های شناور باید از پس‌زمینه قابل تشخیص باشند.

```text
    ├── services/
    └── utils/
```

### Implementation rules

* رنگ‌ها و اندازه‌ها در یک محل مرکزی تعریف شوند.
* از تکرار بی‌دلیل Style Sheetها جلوگیری شود.
* منطق کسب‌وکار از رابط کاربری جدا باشد.
* دسترسی به پایگاه داده در لایه مستقل انجام شود.
* عملیات طولانی رابط کاربری را مسدود نکنند.
* خطاها مدیریت شوند و پیام مناسب به کاربر نمایش داده شود.
* طراحی کامپوننت‌ها تا حد ممکن قابل استفاده مجدد باشد.

### Design tokens

تمام مقادیر طراحی باید در یک محل مرکزی نگهداری شوند تا تغییر تم یا اصلاح رنگ‌ها به تغییرات پراکنده نیاز نداشته باشد.

## 21. Quality Checklist

قبل از انتشار هر نسخه بررسی شود:

* [ ] تمام صفحات با تم تیره هماهنگ هستند.
* [ ] RTL در همه پنجره‌ها درست عمل می‌کند.
* [ ] فونت فارسی در تمام سیستم‌ها قابل‌خواندن است.
* [ ] رنگ‌ها از توکن‌های مرکزی استفاده می‌کنند.
* [ ] دکمه‌ها تمام وضعیت‌های لازم را دارند.
* [ ] فرم‌ها پیام خطای مناسب دارند.
* [ ] جداول خوانا و قابل فیلتر هستند.
* [ ] گزارش‌ها با داده‌های واقعی مطابقت دارند.
* [ ] خروجی CSV در Excel قابل‌استفاده است.
* [ ] اندازه پنجره روی نمایشگرهای مختلف مناسب است.
* [ ] هیچ عنصر رابط کاربری بدون کاربرد وجود ندارد.
* [ ] عملیات حذف و تغییر اطلاعات ایمن هستند.
* [ ] رابط در استفاده طولانی‌مدت خسته‌کننده نیست.

---

## Final Design Direction

ActivityFlow باید حس یک محصول دسکتاپ مدرن و حرفه‌ای را منتقل کند: پس‌زمینه تیره و عمیق، بنفش کنترل‌شده، تایپوگرافی فارسی دقیق، فاصله‌گذاری منظم، کارت‌های ظریف و تجربه کاربری روان.

**هدف نهایی:** رابطی که در نگاه اول حرفه‌ای به نظر برسد، در استفاده روزانه راحت باشد و در تمام بخش‌ها یک هویت بصری منسجم داشته باشد.
